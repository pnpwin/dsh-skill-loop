# Skill loop для DeepSeek Harness

[GitHub](https://github.com/pnpwin/dsh-skill-loop) · MIT · `@pnpwin/dsh-skill-loop` · v0.1.3

## Установка из GitHub

В DSH установите bundle `github:pnpwin/dsh-skill-loop#v0.1.3` через Plugin Manager. Для агента:

```json
{"action":"install_bundle","target":"github:pnpwin/dsh-skill-loop#v0.1.3","enabled":true}
```

DSH runtime: **0.2.2-rc.1**, Node.js ≥22. Это готовые ESM-модули: установка не запускает build/prepare/install scripts и не скачивает runtime dependencies. GitHub-репозиторий публичный; флаг `private` в манифесте лишь предотвращает случайную публикацию в npm.

При переходе с локального прототипа сначала отключите старый bundle, затем установите GitHub-версию и удалите старую пакетную зависимость. Domain `local_skill_loop`, row/provider IDs и формат записей сохранены: навыки, предложения, режим и история не переименовываются и не удаляются.

## Структура и правило разработки

**Весь исполняемый код находится в `src/`.** В корне допускаются только документация/лицензия, Git metadata и файлы обнаружения DSH (`package.json`, `cordis.patch.yml`). Существующие каталоги `tests/` и `locale/` не переименовываются и не переносятся. Тестовый код остаётся в `tests/`.

```text
src/                  # Host entry, runtime, core, projection, prompts, build checks, icon
  index.js            # exports["."] — точка загрузки DSH
  CONTRACT.md         # исторические проектные заметки; не входит в release package
tests/                # unit/integration/packaging tests
locale/               # en/ru metadata
package.json          # DSH bundle manifest + exports
cordis.patch.yml      # Loader patch
README.md
LICENSE
UPSTREAM.md
.gitignore
```

`npm run build` проверяет структуру, exports, модули и ресурсы без генерации кода в корне. `npm run pack:release` сохраняет архив в игнорируемый каталог `.release/`, а не в корень.

Небольшой нативный механизм: **наблюдение → атомарные уроки → новый навык / новая ревизия → подтверждение на обкатке → auto → последующие исправления**.

Вдохновлён [RHI](https://arxiv.org/abs/2607.15524), [Hermes Curator](https://github.com/NousResearch/hermes-agent/blob/6b21d0564de0492e2ebd0d8f63fca86c03b5c892/agent/curator.py) и [ECC How it works](https://github.com/affaan-m/ECC/blob/d2ef2680594f9a17526a6e1a2e18b3d242c5d17b/skills/continuous-learning-v2/SKILL.md#how-it-works). Это самостоятельная простая реализация, не копия этих систем и не обучение весов модели.

## Что автоматизировано

После завершения обычного пользовательского хода проверяются новые видимые сообщения и результаты shell-тестов. При сигнале полезного успеха, исправления, антипаттерна или вмешательства запускается **один ограниченный вспомогательный вызов модели DSH, без инструментов**.

Он создаёт до трёх атомарных уроков и до одного предложения навыка. Передаются релевантные управляемые навыки целиком, чтобы куратор мог минимально улучшить существующий навык вместо создания дубля. У ревизии сохраняются причина изменения и ссылки на события. Пустой ответ допустим: нет квоты на новые skills или удаления.

Агент может вызвать `skill_loop` с `action: reflect` и кратким пояснением после значимого самоисправления, которое не распознали эвристики. Это запрос анализа на конец хода, **не подтверждение успеха**.

## Два режима

- **review — установлен по умолчанию для обкатки.** Навыки готовятся автоматически, но не становятся активными до `/skill-loop approve ID`.
- **auto — включается пользователем явно, отдельно для каждого рабочего каталога.** Будущие подтверждённые предложения публикуются автоматически. Смена режима не публикует задним числом всю очередь.

Режим не переключается сам по числу одобрений. При необходимости его можно вернуть в review.

## Что считается подтверждением

Автоматически:

- короткое однозначное сообщение настоящего пользователя: «Теперь работает», «Всё работает», «Тесты прошли», `It works`, `All tests passed`;
- распознанный запуск тестов/typecheck с явным кодом завершения 0 и без признаков ошибок. В DSH v0.2.2 native код берётся из `job/settled`, строго сопоставленного по session owner, call ID, label и текущему turn с `tool/result`; в provenance нужны оба события. Поддержаны простые `node --test`, `bun test`, npm/pnpm/yarn test/typecheck, vitest/jest, tsc --noEmit. Shell chains/pipes, build-only, generic echo, списки тестов, очевидные zero-tests/skip-only результаты не подтверждают успех.

`isError:false`, отсутствие исключения, «готово» от агента и сам текст предложения **не являются подтверждением**. Позднее отрицательное свидетельство в той же выборке снимает подтверждение. Предложение/урок должны ссылаться на фактический источник подтверждения, а не только на утверждение ассистента.

Эвристики намеренно консервативны и не покрывают все языки, runners и формулировки. Нельзя доказать причинную связь теста и исправления одним regex. Native-корреляция v0.1.2 поддерживает короткие foreground bash-проверки. Для long-running/background задач без полного связанного результата подтверждение не выдаётся (fail-closed); нужен явный проверенный результат или human confirm. Поэтому стартовый режим — review.

### Исправление v0.1.3

Live smoke-тест дополнительно выявил, что стандартный отчёт Node содержит `cancelled 0`. Нулевые счётчики failures/errors/cancellations/timeouts теперь исключаются из признаков ошибки; положительные счётчики и настоящий native cancelled по-прежнему блокируют подтверждение. Интеграционный fixture включает полный реальный формат Node spec summary, а не одни точки/stdout.

### Исправление v0.1.2

Живая проверка выявила отличие от прежних fake Host fixtures: успешный `bash` возвращает обычный stdout, а exit status DSH хранит отдельно в `job/settled`. Старый parser не видел этот статус и оставлял такие результаты unconfirmed. Исправление использует durable native outcome, не доверяет одному `isError:false`, требует ссылки на native outcome и результат. Посторонний успешный `git status`/read после теста больше не отменяет подтверждение; реальная ошибка и неизвестный результат следующей verification всё ещё отменяют. Projection revision повышена; storage domain и пользовательские данные не менялись.

Если полезное предложение осталось unconfirmed, пользователь может явно удостоверить проверенный результат командой `/skill-loop confirm ID`. Эта команда сохраняет human receipt, **сама не публикует**. Затем `/skill-loop approve ID`.

## Команды

Вводите как обычные slash-команды DSH; обработка управления не требует LLM.

| Команда | Действие |
|---|---|
| `/skill-loop status` | Режим, состояние, бюджет и очередь текущего проекта |
| `/skill-loop pending` | Подготовленные предложения |
| `/skill-loop show ID` | Содержимое, причины, источники и сравнение старого/нового |
| `/skill-loop confirm ID` | Явно подтвердить, что исходный результат проверен и успешен; без публикации |
| `/skill-loop approve ID` | Опубликовать подтверждённое предложение |
| `/skill-loop reject ID` | Отклонить предложение |
| `/skill-loop mode auto` | Автопубликация будущих подтверждённых предложений |
| `/skill-loop mode review` | Вернуть обкатку с подтверждением |
| `/skill-loop analyze` | Анализ последнего завершённого нового окна; не подтверждает успех и не обходит лимиты |
| `/skill-loop curate` | Возможные пересечения навыков по ключевым словам; ничего не удаляет |
| `/skill-loop archive NAME` | Скрыть управляемый навык, сохранив версии |
| `/skill-loop restore NAME` | Вернуть управляемый навык |
| `/skill-loop rollback NAME N` | Создать новую ревизию из сохранённой версии N |
| `/skill-loop pause`, `/skill-loop resume` | Приостановить/возобновить обучение каталога |

Инструмент агента `skill_loop` имеет только `status`, `read`, `reflect`. **Подтверждение, approve, mode, архив и rollback доступны только human command channel**, не инструменту куратора. Это граница API, не sandbox для произвольного кода с полным доступом к машине.

## Как хранятся и используются навыки

Данные сохраняются штатным DSH `storageDomain` в домене `local_skill_loop`. Отдельный сервер, SQLite-движок, embeddings и установка зависимостей не нужны.

Опубликованные `learned-*` — настоящие нативные skills через workspace-filtered SkillProvider. Они доступны стандартному инструменту `skill` и появляются в каталоге при следующей сборке контекста. Это виртуальные provider-backed навыки, а не отдельные файлы, перезаписывающие пользовательскую библиотеку. Для просмотра/копирования используйте `show`/`read`. Отключение bundle сохраняет domain state, но убирает provider из каталога.

Scope — **канонический абсолютный рабочий каталог**, не git remote. Подкаталог или worktree является отдельным scope. Это намеренная простота; глобальной автопубликации между репозиториями нет. После смены cwd старые свидетельства отсекаются, включая ручной analyze. Вложенные subagents не обучают библиотеку; обычный пользовательский fork может обучать только по собственным новым событиям, не по унаследованному префиксу.

Наблюдение начинается после активации/перезапуска плагина; автоматического чтения и переобработки всей старой истории нет. Manual analyze также не обходит этот предел. Локальная очередь и статусы сохраняются между перезапусками.

## Ограничения и затраты

Defaults:

- до 12 попыток анализа на рабочий каталог в сутки (UTC);
- пауза между автоматическими анализами — 60 секунд;
- input JSON ≤16 000 символов; system prompt — дополнительный постоянный overhead;
- output cap 3000 токенов; timeout 45 секунд;
- 50 активных / 100 всех навыков, 50 pending / 100 всех proposals;
- 200 уроков, 100 записей запусков; последние 10 ревизий на навык.

Попытка резервируется до запроса. Ошибки/отмены тоже учитываются в лимите: нет циклических повторов или recursive reviewers. Повтор того же окна не вызывает модель повторно. Сигнал во время cooldown пропускается, не создаёт бесконечную очередь; в пределах лимита можно явно вызвать analyze после завершения работы.

По умолчанию используется выбранная в сеансе модель. В Config можно задать `provider`/`model` и лимиты. Температура не навязывается. Хранение локальное; **обработка идёт выбранному провайдеру DSH**, если это облачная модель. Перед передачей текст очищается эвристическим secret-фильтром и ограничивается; это не полный DLP/PII classifier. Не включайте обучение в каталогах с данными, которые нельзя отправлять этому провайдеру. Для отдельного scope есть pause, для плагина — enabled.

## Безопасность и честная оценка

- Куратор не получает tools, терминал, write-доступ к библиотеке или возможность менять права.
- Меняются только собственные `learned-*`; встроенные/чужие skills не перезаписываются.
- Текст наблюдений и прошлых skills помечен как недоверенные данные.
- JSON/schema, ссылки на источники, baseRevision, дедупликация и секреты проверяются кодом. Изменения атомарно сохраняются одной записью проекта; ошибка сохранения не меняет активный state.
- Конкурирующая устаревшая ревизия не публикуется. Rollback увеличивает номер ревизии и инвалидирует старые предложения.
- Новое пользовательское сообщение, отмена ручного analyze, pause/disable/unload отменяют ещё не начатую публикацию; перед атомарным сохранением есть повторная проверка. Уже начатую/завершённую durable запись нельзя отозвать задним числом — используйте rollback. Выгрузка ждёт фоновые jobs.
- Куратор не считает число открытий навыка или удачный tool call доказанным ростом качества.
- Проверки здесь — **источник + структура + согласованность**, а не независимый benchmark, semantic theorem или исполнение предложенного regression suite. RHI-inspired означает историю контролируемых ревизий, а не полную реализацию научной оптимизации.
- Архивирование и rollback восстанавливают навыки, но не отменяют последствия уже выполненных агентом действий.

- 96 unit/integration tests прошли; в том числе scope, обязательные источники подтверждения, review/auto, отмена, crash/restart status, бюджет, stale revisions, rollback и zero-tests.

- Первая попытка активации выявила обязательный snake_case имени storage unit; исправлено на `local_skill_loop`, и ограничение добавлено в интеграционные тесты.
- Зарегистрированные поля Config и установленные locale-ресурсы проверены. Отрисовка иконки/локализации в GUI визуально не проверялась.

Проверены запуск на turn/end, модельный JSON-ответ, обработка и запись результата в native domain. На этом окне модель не предложила полезного навыка — пустой результат допустим, мусорная публикация не требуется. Семантическое качество непустых предложений ещё не оценено; публикация остаётся под review.
- Фактический A/B замер first-turn prompt tokens не выполнен; постоянная секция guidance и схема одного инструмента добавляют контекст, а анализ имеет отдельный ограниченный бюджет.
