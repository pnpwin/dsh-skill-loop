# Настройка бюджетов обучения

В v0.2.0 бюджеты уже являются полями нативной Config-схемы плагина `@pnpwin/dsh-skill-loop`, entry `include:local-skill-loop`. Это не константы, требующие изменения исходников. Изменяйте конфигурацию штатным редактором DSH (native ConfigEditor); не редактируйте вручную package/patch-файлы профиля. Обычные поля применяются через штатный lifecycle Loader, поэтому изменение бюджета может перезапустить runtime плагина.

| Поле | По умолчанию | Допустимо | Назначение |
|---|---:|---:|---|
| `dailyReviews` | 12 | 1–100 | Максимум циклов в сутки для проекта |
| `maxAuxCallsPerDay` | 12 | 1–200 | Общий максимум модельных вызовов Reflector + Curator, включая неуспешные |
| `maxInputChars` | 16000 | 4000–24000 | Суммарный JSON payload двух ролей; не число токенов |
| `maxOutputTokens` | 3000 | 1000–6000 | Общий output-бюджет: 1/3 Reflector, 2/3 Curator |
| `timeoutMs` | 45000 | 5000–120000 | Общий deadline одного цикла в миллисекундах |
| `cooldownMs` | 60000 | 0–3600000 | Минимальный интервал между циклами |
| `verificationMaxCalls` | 18 | 1–100 | Отдельный лимит явной проверки кандидата |
| `verificationTimeoutMs` | 120000 | 5000–300000 | Deadline явной проверки кандидата |

Один цикл может использовать два вызова. Пустая рефлексия корректна: Curator пропускается, второго вызова нет. Увеличение `dailyReviews` само по себе не снимает ограничение `maxAuxCallsPerDay`.

Настройки относятся к профилю; счётчики расхода хранятся отдельно для каждой канонической рабочей директории. Изменение лимита **не обнуляет** счётчики. Суточный период вычисляется по UTC: для Москвы сброс дня соответствует 03:00 МСК. Для запуска нужен новый подходящий завершённый эпизод; изменение суток само по себе не запускает фоновую задачу.

Бюджет не меняет полномочия: режим review остаётся review; подтверждение результата, проверка кандидата и разрешение публикации независимы. Нулевое число активных навыков означает, что pending-предложения ещё не применяются.

## Временный тест

При текущем расходе 12 циклов / 12 вызовов значения `dailyReviews=13` и `maxAuxCallsPerDay=14` разрешают максимум один дополнительный цикл и два его вызова. После теста восстановите точные прежние значения/отсутствие полей, сохранив прочие настройки. Расход не откатывайте: при возвращении лимита 12 использованные 13/14 остаются израсходованными до следующего дня.

Нельзя вызывать ConfigEditor.edit прямо из активации helper-плагина: активация выполняется внутри HMR-транзакции, вложенная транзакция отвергается. Изменение выполняется отдельным явно разрешённым действием после активации. Для теста применяется пяти­минутный автоматический guard восстановления; перед удалением helper нужно проверить фактическое восстановление.
